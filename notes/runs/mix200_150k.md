# Run card: `mix200_150k`

GR00T N1.7 fine-tuned on all 50 RoboTwin 2.0 tasks with 50 clean + 200 randomized demos
per task (12,500 episodes), 150k steps, a checkpoint every 15k (all kept) so the
learning curve can be evaluated. Recipe otherwise identical to `50task_60k` (the
50-clean-demos-per-task model: 42.6% clean / 9.7% randomized at checkpoint-60000).

## Command

From the repo root, at commit `8dacfd9`:

```
GPUS=3,5,0,7 setsid -f nohup bash gr00t/run_mix200.sh > logs/run_mix200.log 2>&1 < /dev/null
```

`gr00t/run_mix200.sh` skips its data steps (the dataset is ready) and runs:

```
OMP_NUM_THREADS=8 DATALOADER_NUM_WORKERS=32 RUN=mix200_150k DATASET=mix200 GPUS=3,5,0,7 \
  MAX_STEPS=150000 SAVE_STEPS=15000 SAVE_TOTAL_LIMIT=10 GLOBAL_BATCH_SIZE=64 bash gr00t/train.sh
```

If training exits before step 150000, it waits 5 min, waits until each of the same GPUs
has >= 45 GB free, and resumes from the latest checkpoint (up to 3 attempts; logs of
earlier attempts are kept as `logs/train_mix200_150k_seed0.before_attempt<N>.log`).

Final launch command (from the training log):

```
torchrun --nproc_per_node=4 --master_port=29617 gr00t/experiment/launch_finetune.py \
  --base_model_path nvidia/GR00T-N1.7-3B \
  --dataset_path data/lerobot/RoboTwin-mix200_150k-aloha_agilex-joint \
  --embodiment_tag NEW_EMBODIMENT --num_gpus 4 \
  --output_dir RoboTwin/XPolicyLab/policy/GR00T_N17/checkpoints/RoboTwin-mix200_150k-aloha_agilex-joint-0 \
  --save_steps 15000 --save_total_limit 10 --max_steps 150000 \
  --warmup_ratio 0.05 --weight_decay 1e-5 --learning_rate 1e-4 --global_batch_size 64 \
  --color_jitter_params brightness 0.3 contrast 0.4 saturation 0.5 hue 0.08 \
  --dataloader_num_workers 32 --shard_size 1024 --num_shards_per_epoch 100000 \
  --episode_sampling_rate 0.1 \
  --modality_config_path RoboTwin/XPolicyLab/policy/GR00T_N17/configs/aloha_agilex_config.py \
  --experiment_name RoboTwin-mix200_150k-aloha_agilex-joint-0
```

(`RoboTwin-mix200_150k-aloha_agilex-joint` is a symlink to `RoboTwin-mix200-aloha_agilex-joint`.)

- **Sources.** Clean: RoboTwin's XPolicyLab-format `demo_clean` release (same pieces as
  `50task_60k`). Randomized: RoboTwin's raw `<task>/aloha-agilex_randomized_500.zip`,
  episodes 0–199, converted to XPolicyLab format by `gr00t/fetch_randomized.py`
  (state[t] = raw joint state t, action[t] = raw joint state t+1; checked field by
  field against RoboTwin's own clean release).
- **Cameras.** `cam_high` ← head camera, plus the left and right wrist cameras; 320×240,
  15 fps, AV1.
- **State and action.** 14-dim joint positions: per arm, 6 joints + gripper.
- **Instructions.** One sentence per episode, picked at random from the episode's
  "seen" instructions (11,293 distinct).
- **Merge order.** Episode indices are: clean (tasks sorted), then
  `demo_randomized0`–`3` (episodes 0–49, 50–99, 100–149, 150–199), each with tasks sorted.
- **Build.** `gr00t/build_mix200.sh`: convert each (group, task) to its own piece →
  downgrade each piece to v2.1 → `gr00t/merge_v2.py` → GR00T's `process_data.sh` (stats,
  modality) → `gr00t/check_dataset.py`.
- **Verified** (`logs/verify_mix200.log`):
  - Every video has one frame per step; 12,500 episodes.
  - `gr00t/verify_dataset.py`: every episode's state and action are identical to its
    source file; every instruction GR00T reads is one of the source's sentences.
  - 750 video frames are within 1.6/255 of the source images.
  - Stats are finite.

## For analysis

- **The checkpoints are one run, not separate runs.** checkpoint-15000 is a model from
  early in a 150k cosine schedule, at a high learning rate. It is not a model trained
  for 15k steps with its own schedule.
- **Mix.** By frames the mix is ~20% clean, ~80% randomized. No reweighting by setting
  or task was added; GR00T's default sampler decides the exact proportions.
- **Wound-up joints.** 169 of the 10,000 randomized episodes (1.7%; ~0.5% of frames, none
  clean) have joint angles beyond ±3.5 rad, up to 8.5 rad: smooth motions where a joint
  wound past a full turn. They are kept as RoboTwin recorded them. Percentile
  normalization makes their effect on scaling negligible (the 1st/99th percentiles match
  the clean-only dataset's).
- **Speed.** The dry run with 16 workers and this run with 32 both ran at ~2.3 steps/s
  with the GPUs ~40–60% busy, so data loading (not worker count) limits speed. Future
  speedup to look at.

## Evaluation plan (agreed 2026-10-30)

Every eval below reuses the exact scenes the old model (`50task_60k`, checkpoint-60000)
was scored on, so results compare scene by scene.

**Why one job per shard.** Shard k of an eval runs consecutive valid seeds from
100000·(k+1) (`gr00t/benchmark.sh`). `gr00t/paired_queue.py` reads the old eval's client
logs and writes one queue line per old shard (task, setting, episodes, seed index).
Workers run with `MAX_SHARDS=1`, so each line runs as exactly one shard: 4 workers per
GPU give 4 streams per GPU. Retries after a crash go to seed index +1000, so they never
reuse another job's seeds or log file.

| Queue (in priority order) | Checkpoint | Tasks | Settings | Episodes |
|---|---|---|---|---|
| `queue_mix200_s1_150k` | 150000 | 10 tasks below | clean + randomized, old layout (~20 each) | 401 |
| `queue_mix200_s1_60k` | 60000 | same 10 | same | 401 |
| `queue_mix200_s2_150k` | 150000 | the other 40 | randomized old layout (~20) + clean first 10 | 1,216 |
| `queue_mix200_s3_120k`, `_90k`, `_30k` | 120000, 90000, 30000 | same 10 | randomized, old layout | 201 each |

- **The 10 tasks** are `pick_dual_bottles`, `place_object_stand`, `move_pillbottle_pad`,
  `place_empty_cup`, `place_phone_stand`, `move_can_pot`, `dump_bin_bigbin`, `handover_mic`,
  `grab_roller`, `click_bell`. They were picked because the old model scored ≥ 30% clean
  (so the skill is learned), randomized has room to rise, and episodes are cheap
  (3.5–8.5 stream-min). They are easier than average, so their numbers compare models
  but are not a benchmark score.
- **Estimated cost**, from the old eval's measured stream-minutes per episode ÷ 60 ÷ 4
  streams per GPU, on 4 GPUs:
  - first two queues: 20.8 GPU-h;
  - the 40-task queue: 77.6 GPU-h;
  - the last three: 14.2 GPU-h;
  - total 112.6 GPU-h, ~28 h.
- **Learning-rate caveat.** The new model's checkpoint-60000 was taken at learning rate
  7.0e-5; the old model's checkpoint-60000 at 7.6e-14, the end of its schedule (both
  read from `trainer_state.json`). Equal steps is not like-for-like.
- **Queues** are copied in `notes/runs/mix200_150k_eval_queues/`. Regenerate with:

  ```
  python3 gr00t/paired_queue.py RoboTwin-50task_60k-aloha_agilex-joint-0 60000 <setting> [--max-eps 10] <tasks...>
  ```

